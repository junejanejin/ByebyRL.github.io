1. RL 关键流程

RL（强化学习）：模型经过推理生成 response，reward manager 对 response 打分，训练拿到 response 和分数，计算策略更新量、更新权重，权重同步回推理引擎，进入新一轮训练

分五步：①初始化 → ②推理（生成）→ ③评分 → ④训练（compute logp → 前向 → 反向）→ ⑤权重回传，循环。展开：第一章 RL 世界观。

2. RL 框架构成

RL 训练框架由一个调度层和训推两个引擎组成，三部分：

  1. 调度层（veRL + Ray）：编排全流程；
  2. 推理引擎（vLLM/SGLang）：生成 response；
  3. 训练引擎（FSDP/Megatron）：算 loss 更新权重。

4. RL 实操

步 动作 命令 说明
1 拉取代码 git clone verl && uv sync v0.9.1，依赖由 uv.lock 锁定
2 数据集格式转换 python examples/data_preprocess/gsm8k.py 产出 train/test parquet
3 下载模型 huggingface-cli download Qwen/Qwen3-8B 基座模型
4 启动训练 bash examples/ppo_trainer/run_qwen3_8b_fsdp.sh 首跑先缩规模：batch 32、response 1024、10 步验证链路
5 监控 观察每一步训练指标 wandb 面板，关注以下曲线

入门观察指标：

曲线（wandb） 正常 出问题
critic/rewards/mean 持续爬升 骤降 → 查截断率；跌至随机水平 → 查权重同步
actor/entropy 缓慢下降 快速下降 = 回答趋同，学习将停滞
response_length/clip_ratio < 5% 偏高 = 回答被截断，reward 受截断损失 → 放开长度

logpdiff 第一遍应 ≈ 0（数值噪声级）；第一遍就到 1e-2 以上说明权重同步或数值路径有问题。

5. 常用调参

症状 动作
OOM 调整切分（TP/PP 分担单卡显存）、减 batchsize、offload、重计算等
更新不充分 加 ppo_epochs、调 mini/micro 配比
推理速度慢 先看 KV cache 有没有打满：gpu_memory_utilization 是否给足、并发（max_num_seqs）是否受限、日志有无 preemption；KV 打满仍慢再调分块预填与引擎参数
